# Log de Migración — `general`

> Seguimiento feature por feature de la migración al nuevo código base.
> Estados: `PENDIENTE` · `EN PROGRESO` · `MIGRADO` · `VERIFICADO`.
>
> **Contexto de arquitectura (2026-06-26):** este log cubre la migración del **front** del módulo `general`.
> El backend adoptó la arquitectura modular **ADR-0009** (verticales autocontenidos `{Módulo}.Domain/
.ExternalPorts/.Application/.Infrastructure/.Controllers`; el proyecto de puertos externos se llama
> `ExternalPorts`, antes `Contracts`). El **próximo vertical es budget** (front + API) por forward-port —
> ver `Api/Docs/plan-forward-port-budgeting.md`. El shell del front (core/layout/shared + ABMs de `general`)
> es la base sobre la que se montan los features de cada vertical nuevo.
>
> **E2E de browser (actualización 2026-06-25):** suite **Playwright** (50 casos verde; ver
> [`../e2e/`](../e2e/) y [`e2e/`](./e2e/)). Estrategia = capa fina de smoke con **Usuarios como CRUD
> canónico**; además tienen smoke propio las pantallas con jornada cross-feature: errors (404/403),
> perfil, auditoría (filtros/detalle) y logs. El resto de los ABMs **no** lleva e2e de browser propio
> (su detalle ya está cubierto por integración de API + specs de componente) → figuran **N/A por
> estrategia**, y las que sí tienen cobertura van con ✅ + el caso.
